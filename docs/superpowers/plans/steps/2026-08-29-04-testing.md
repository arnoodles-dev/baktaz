# Steps Feature Testing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Write comprehensive unit tests, widget tests, golden tests, and serverpod endpoint integration tests covering all Steps Feature logic, UI, and backend API flows including HealthKit/Health Connect platform integration, step synchronization, device management, and one-authoritative-provider rule enforcement.

**Architecture:** Use `mockito` for mocked client and repository generation. Test Cubit state transitions with `bloc_test` and pure Dart `test`. Implement UI visual golden tests with `alchemist` under `test/widget/steps/`. Conduct serverpod integration tests using `withServerpod` under `test/integration/steps/`.

**Tech Stack:** `flutter_test`, `test`, `mockito`, `alchemist` (15% tolerance), `serverpod_test`.

**Spec:** `docs/superpowers/specs/Steps/Index.md`

## Global Constraints

- Tests written ONLY AFTER all implementation tasks are completed.
- Target 100% coverage for Cubits and Repositories.
- Target 80% coverage for UI screens and widgets.
- AAA Pattern (Arrange-Act-Assert) strictly followed.
- Generated mock file resides in `test/utils/generated_mocks.dart`.
- Widget tests = golden tests (Alchemist, 15% tolerance).
- Server integration tests use `withServerpod` for real DB operations.
- Out-of-order sync protection and one-authoritative-provider rule must be explicitly tested.
- Revalidation on app resume must be tested.
