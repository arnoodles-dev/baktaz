
# Steps Data Integration & Step Synchronization Specification
> **Parent Spec:** `docs/superpowers/specs/Steps/2026-08-29-01-overview.md`

**Status:** Approved  
**Version:** 1.0  
**Platforms:** Flutter (iOS + Android), Serverpod backend  
**Health Providers:** Apple HealthKit, Android Health Connect

---

## 1. Overview

This specification defines how the application integrates with:

- **Apple HealthKit** on iOS
- **Android Health Connect** on Android

The goal is to reliably capture daily step counts and make them available for challenges, rewards, and analytics.

---

## 2. Core Principles

### 2.1 Single Source of Truth

The **latest sync** is always authoritative.

```text
❌ Never:
  total = prev_total + delta

✅ Always:
  total = latest_cumulative_value
```

### 2.2 Device-Specific State

Each device tracks its own integration state independently.

- A user can have multiple devices connected.
- Each device has its own permission state.
- Each device has its own sync history.

### 2.3 Platform Abstraction

The app must abstract over:

- HealthKit (iOS)
- Health Connect (Android)

Implementation detail: The Flutter `health` package is recommended as the initial abstraction layer.

### 2.4 Verification Over Assumption

A successful permission dialog does **not** mean data is accessible.

The app must **verify** it can actually read step data before:

- Showing a connected state
- Counting steps toward a challenge
- Displaying sync success

---

## 3. Scope

### 3.1 Included

- Reading step counts from HealthKit / Health Connect
- Syncing step data to the backend
- Tracking which devices are connected
- Re-validating health access on app resume
- Handling Samsung Health edge case on Android
- Multi-device and cross-platform scenarios

### 3.2 Explicitly Out of Scope

- Sleep, heart rate, or other health metrics
- Manual step entry
- Step prediction or estimation
- Offline step counting (pedometer)
- Apple Watch direct integration (use HealthKit aggregation instead)
