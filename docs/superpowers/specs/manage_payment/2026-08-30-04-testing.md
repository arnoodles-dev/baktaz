## 1. Testing Targets & Rules

Per `.agents/rules/testing.md`:
- **Implementation-First Workflow (HARD REQUIREMENT)**: Tests written and executed **only after** all implementation, codegen (`serverpod generate`, `build_runner`), database migrations, and cross-package compilation complete.
- **100% Coverage Target**: `ManagePaymentCubit`, `IPayoutRepository`, `IPaymentRepository`, `ChallengeJoinCubit`, `ChallengeCreateCubit`.
- **80% Coverage Target**: `ManagePaymentScreen`, `EditPayoutDestinationDialog`, `HitPayTokenizeWebview`.
- **AAA Pattern**: Arrange-Act-Assert. Descriptive test names (`returns null when user does not exist`).
- **Mocking**: `mockito` (`@GenerateMocks` in `test/utils/generated_mocks.dart`). Never `mocktail`.
- **Widget Tests = Golden Tests**: Alchemist, 15% tolerance, versioned by date, `--update-goldens`.
- **No Screen Tests**: Only test widgets, not full-screen views. No interface tests.

## 2. Server Integration Tests (`baktaz_server`)

File: `test/integration/features/account/manage_payment_endpoint_test.dart` (uses `withServerpod`).

### Required Test Cases:
1. **Max Saved Payment Methods Limit (5)**:
   - Seed 5 `SavedPaymentMethod` records for a user.
   - Calling `savePaymentMethodToken` throws `ValidationFailure` with code `'MAX_SAVED_PAYMENT_METHODS_REACHED'`.
2. **Default Payment Method Auto-Reassignment**:
   - Seed 3 methods where `methodA` is default (`isDefault: true`, `createdAt: T0`), `methodB` (`createdAt: T1`), `methodC` (`createdAt: T2`).
   - Call `deletePaymentMethod(methodA.id)`.
   - Assert `methodB` is now `isDefault: true`.
3. **Payout Destination Regex Validation**:
   - GCash with valid `09171234567` passes; invalid `08171234567` throws `ValidationFailure('INVALID_PAYOUT_ACCOUNT_NUMBER')`.
   - Maya with valid `09181234567` passes; invalid `12345` throws `ValidationFailure('INVALID_PAYOUT_ACCOUNT_NUMBER')`.
   - Bank with valid `1234567890` and `bankName: "BDO"` passes; invalid non-digit or missing `bankName` fails.
4. **Payout Destination Overwrite & Audit Logging**:
   - Call `upsertPayoutDestination` twice for same user with different numbers.
   - Assert single record remains in `payout_destination` table.
   - Assert audit log table (`audit_logs`) contains 2 records (`created` and `overwritten`).

## 3. Flutter Unit & Widget Tests (`baktaz_flutter`)

### 3.1 Cubit Unit Tests (`test/unit/manage_payment_cubit_test.dart`)
- Verify `ManagePaymentCubit` extends `CubitSignal<ManagePaymentState>` with `initialState:` constructor.
- Verify `safeRun` wrapping and `FailureHandler` side-effect routing (Pattern B).
- Verify initial load fetches `PaymentPayoutSummary`.
- Verify `savePaymentMethodToken` handles success and surfaces limit failure via `FailureHandler`.
- Verify auto-reassignment reflects in loaded state after deletion.
- Verify `ChallengeJoinCubit` and `ChallengeCreateCubit` block action when active `PayoutDestination` is missing.

### 3.2 Widget & Golden Tests (`test/widget/account/manage_payment_screen_test.dart`)
- **Max Methods UI State**: Verify "+ Add Payment Method" (`BaktazButton`) is disabled and `"Max 5 methods"` (`BaktazStatusBadge`) is visible when 5 methods are present.
- **HitPay Navigation Intercept**: Verify webview `onNavigationRequest` intercepts callback URL, extracts query params, closes webview, and calls cubit.
- **Overwrite Warning Dialog**: Verify `EditPayoutDestinationDialog` presents `ConfirmationDialog` when replacing an existing payout destination.
- **Paid Challenge Block Dialog**: Verify attempt to join paid challenge without payout destination opens warning dialog (`context.i18n.manage_payment.payout_destination_required_for_paid_challenge`) redirecting to `/account/payment`.
- **Alchemist Goldens**: 15% tolerance, stored in `test/widget/account/goldens/` with `macos` and `ci` subfolders.
