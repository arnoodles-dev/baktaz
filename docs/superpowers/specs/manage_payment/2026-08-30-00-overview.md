## 1. System Overview & Scope

The `/account/payment` route in Baktaz delivers a single unified screen for managing tokenized saved payment methods (cards/e-wallets via HitPay) and a strictly enforced single active payout destination (GCash, Maya, or Bank Account).

### Core Principles:
1. **Single Unified Screen (`ManagePaymentScreen`)**: Navigated from `AccountPage` (`/account`) via the "Manage Payment & Payouts" list row (`AppListRow` / `BaktazCard` wrapper).
2. **Configurable Max Saved Payment Methods Limit**:
   - `AppConfig.maxSavedPaymentMethods = 5` defined in `baktaz_server` (`lib/src/app/config/app_config.dart`).
   - `savePaymentMethodToken` RPC throws `ValidationFailure('MAX_SAVED_PAYMENT_METHODS_REACHED')` if user attempts to save > 5 methods.
   - Flutter UI disables "+ Add Payment Method" button when `savedMethods.length >= 5` and displays a `"Max 5 methods"` badge (`BaktazStatusBadge`).
3. **Default Payment Method Auto-Reassignment & Single Transaction**:
   - Setting a new default payment method updates `isDefault = true` for target and `isDefault = false` for all other user methods in a single database transaction (`session.db.transaction`).
   - Deleting the active default payment method automatically assigns `isDefault = true` to the user's next oldest method (`createdAt ASC`) in the same database transaction (`session.db.transaction`).
4. **HitPay Tokenization Integration & Result Tuple**:
   - Flutter webview (`HitPayTokenizeWebview`) loads HitPay tokenizer URL.
   - Intercepts callback URL (`https://baktaz.app/payment/token-callback?token=...&type=...&last4=...&brand=...`) via `onNavigationRequest`.
   - Webview extracts query parameters, pops result tuple `(token, type, last4, brand)`, and triggers `ManagePaymentCubit.savePaymentMethodToken(...)`.
5. **Strict Single Active Payout Destination, Atomic Upsert & Local Form Validation**:
   - Enforced via PostgreSQL `unique: true` index on `payout_destination.userId` (`payout_destination.user_id_unique_idx`) for atomic upsert.
   - Local form validation regex on account numbers in `EditPayoutDestinationDialog`: GCash (`^09\d{9}$`), Maya (`^09\d{9}$`), and Bank (`^\d{10,16}$`). Disables submit button if invalid.
   - In-place overwrite triggers a `ConfirmationDialog` in Flutter UI warning the user before submitting replacement payout destination.
   - Server logs audit event to `audit_logs` table upon destination creation, overwrite, or deletion.
6. **Hard Block on Paid Challenges**:
   - `ChallengeJoinCubit` and `ChallengeCreateCubit` validate that the user has an active `PayoutDestination`.
   - If missing when attempting to join or create a paid challenge, the action is blocked and user is routed to `/account/payment` with warning dialog: *"You must set up a payout destination before joining or creating a paid challenge."*
7. **Repository & Service Layer Architecture & RPC Error Serialization**:
   - Backend repositories (`IPaymentRepository`, `IPayoutRepository` interfaces in `domain/interface/`, implementations in `data/repository/`) are registered as `@LazySingleton` and orchestrated by `AccountEndpoint`, `PaymentEndpoint`, and `PayoutEndpoint`.
   - Serverpod repository throws typed `ApiException` models (`ValidationFailure`, `DatabaseFailure`) serialized via RPC.
   - Direct HTTP interaction with HitPay API is encapsulated exclusively in `HitPayService` in `data/service/` (`.agents/rules/serverpod-architecture.md`).
8. **Flutter Cubit & Pattern B Error Handling**:
   - `ManagePaymentState.loaded` parameters: `savedMethods`, `payoutDestination`, `isSubmitting`, `isTokenizing`.
   - `ManagePaymentCubit` extends `CubitSignal<ManagePaymentState>` with `initialState:` named constructor (`.agents/rules/flutter-architecture.md`, `state-management-architecture.md`).
   - Uses immutable `state.copyWith(isSubmitting: true)` / `state.copyWith(isTokenizing: true)` for inline actions to preserve UI state.
   - Async repository calls wrapped in `safeRun(onException: _failureHandler.handleException)` and `FailureHandler` side effects without holding `Failure` objects inside `ManagePaymentState` (`.agents/rules/error-handling-architecture.md`).
9. **Design System & Localization**:
   - UI constructed exclusively using `baktaz_shared` wrappers (`BaktazCard`, `BaktazButton`, `BaktazStatusBadge`, `BaktazTextField`, `BaktazSectionHeader`, `ConfirmationDialog`).
   - User-facing text loaded via `context.i18n.manage_payment.*` without hardcoded strings (`.agents/rules/design-system.md`).
10. **Testing & Verification**:
    - Adheres to Implementation-First Workflow: tests created only after code implementation, codegen, database migrations, and cross-package compilation are complete (`.agents/rules/testing.md`).
    - Unit tests in `test/unit/manage_payment_cubit_test.dart`, widget/golden tests (Alchemist 15% tolerance) in `test/widget/account/manage_payment_screen_test.dart`, and server integration tests (`withServerpod`) in `test/integration/features/account/manage_payment_endpoint_test.dart`.
