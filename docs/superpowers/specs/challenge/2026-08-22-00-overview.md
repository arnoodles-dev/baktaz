# Challenge Page Specification — Overview

- **Date**: 2026-08-22
- **Scope**: Full challenge page (`/challenge`) across `baktaz_flutter` + `baktaz_server`
- **Architecture**: 4-state enum (`loading/initial/registered/done`), 3 split repos, hybrid failure handling

## Key Decisions (Q139–Q146)

- **Q139**: After claim payout → cubit resets to `.initial(isPremium:)` — user returns to Trophy Case
- **Q140**: Non-winners auto-reset to `.initial` after challenge completes
- **Q141**: Duration slider 30–120 days for both public and private
- **Q142**: State machine simplified to 4 states. No `failure` state — errors via `BlocSignalPresentationMixin` + `FailureHandler`
- **Q143**: Leaderboard infinite scroll uses distance-based (3 items from bottom), not time-based (500ms)
- **Q144**: Verification plan aligned to 3-repo split (`ChallengeLifecycleRepository`, `ChallengeDiscoveryRepository`, `ChallengeLeaderboardRepository`), no offline caching
- **Q145**: `ChallengeStateSideEffect.onException(Exception)` centralized in root `ChallengePage` widget via `presentationStream`
- **Q146**: Errors during `.registered` state → toast + stay on `.registered`. Never reset to `.initial` on transient errors.
