# Challenge Page Specification — Create

- **Date**: 2026-08-22
- **Parent Reference**: Part of the Challenge Page specification suite — see 00-overview.md

## Route

- `/challenge/create` — Host challenge creation form (Scope.premium required, includes tie-breaker selection)

## 5.7 Challenge Create Screen (`ChallengeCreateScreen`, `/challenge/create`)

- Layout: **"The Ledger Form"** — grouped sections with `BaktazDivider` separators (BASICS, STAKES, RULES, LAUNCH). Single reusable form dynamically showing/hiding type-specific fields.

## Create Flow

1. User taps "Create Challenge" on default view.
2. **Launch Type Bottom Sheet** (`create_launch_type_sheet.dart`) pops up with two options:
   - 🌐 PUBLIC: "Open to anyone. Signup window before challenge starts."
   - 🔒 PRIVATE: "Invite-only. Start when min participants join."
3. User selects type → form opens with `launchType` param driving field visibility.
4. User fills form → taps "Create Challenge" → **Summary Bottom Sheet** (`create_challenge_summary_sheet.dart`) shows all entered values for review.
5. User confirms → checkout/payment (separate feature, stub route).
6. After successful payment → Success Screen with shareable invite code + CTA to view challenge.

## Reusable Form Fields (`challenge_create_form.dart`)

- Challenge Title: Required (`BaktazTextField`).
- Description: Optional (multiline). Shown truncated (1 line, ellipsis) on explore cards; full text on details screen; included in summary sheet.
- Entry Fee: Required slider ₱100–₱10,000.
- Duration: Required slider, min 30 days, max 120 days (same range for both public and private, Q141).
- Max Participants: Required stepper; dynamic floor based on Reward Mode.
- Reward Mode (Q93 Option A): Required radio — 4 options from challenge-mechanics-and-math.md:
  - `winnerTakesAll` — "All In" — 100% to 1st place
  - `top3TieredSplit` — "Podium Model" — recommended default
  - `goalThresholdEqualProfitShare` — "Habit Builder"
  - `milestoneHybrid` — "Hybrid Model"
  Drives which additional fields shown (tie-breaker, step goals, reward breakdown).
- Tie-Breaker: Conditional dropdown + tooltip button. Shown only when Reward Mode is Winner-Takes-All or Top 3 Tiered Split. Hidden for Goal-Threshold and Hybrid (goal-based, no ranking ties). Default pre-selected "Equal Split". Options: `equalSplit`, `suddenDeath`, `consistencyMetric` (Q92 Option A). Required when maxParticipants >= 3 for WTA mode. Tooltip explains how each rule works.
- Launch Type (Q94 Option A): Set by bottom sheet selection, not form field. `public` or `private`. Drives:
- Public: auto-starts at startAt
- Private: host gets Start Challenge Now button
- Schedule UI: same for both (dateRange)
 Drives visibility of launch-specific schedule: `ChallengeSchedule (Q74) — same dateRange UI for both public/private (Q78). durationDays VO reserved but not shown in wizard yet.` (Q74 Option A — sealed union: `dateRange({start,end})` or `durationDays({days})`), replacing raw `DateTimeRange?` fields.

## Dynamic Min Participants Mapping

Floor for max participants stepper:

- Winner-Takes-All: 2
- Top 3 Tiered Split: 3
- Goal-Threshold Equal Profit Share: 2
- Milestone Hybrid: 2

## Schedule Section Model

### Public Schedule

- Duration slider: 30–120 days.
- Initial Phase slider:
  - Minimum: 2 days.
  - Maximum: `AppConfig.publicInitialPhaseMaxDays`.
  - Default: 14 days.
- Start Policy copy: "Auto-starts after initial phase."
- Starts: Read-only computed date = `now + initial phase`.
- Ends: Read-only computed date = `starts + duration`.

### Private Schedule

- Duration slider: 30–120 days.
- Initial Phase slider:
  - Minimum: 1 day.
  - Maximum: `AppConfig.privateInitialPhaseMaxDays`.
  - Default: 30 days.
- Start Policy copy: "Host can start manually once min participants join. Auto-starts after initial phase if min participants joined."
- Starts:
  - Manual when host starts before phase end after minimum participants join.
  - Computed auto date when initial phase ends and minimum participants joined.
- Ends: duration after actual start.

### Private Manual Start Semantics

- Minimum participants reached before phase end:
  - Host can tap `Start Challenge Now` manually.
  - Confirmation dialog (`start_challenge_confirmation_dialog.dart`) shows new Ends date (`start time + duration`).
  - Confirming manual start updates End Date = start time + duration.
- Phase ends with minimum participants reached:
  - Challenge auto-starts.
- Phase ends without minimum participants:
  - Challenge stays pending until 30-day auto-cancel or host archives.

## Summary, Checkout, and Success

- **Summary Bottom Sheet** (`create_challenge_summary_sheet.dart`): Shows all entered values for review before payment.
- Checkout/payment is a separate feature and uses a stub route for this spec.
- After successful payment, show success screen with shareable invite code + CTA to view challenge.

## Header Badge and Launch Type Context

- Header badge shows launch type: `[PUBLIC]` or `[PRIVATE]`.
- Launch Type "Change" action is not needed. Badge is context only; user goes back to change type.

1. **Trophy header**: trophy icon, "Challenge Created!" (headlineMedium), challenge title confirmation ("30-Day Summer Walk is live", bodyMedium)
2. **Invite plaque** (signature element): bordered plaque container (surfaceContainer bg, radiusSmall, 3dp primary border-left accent line) containing:
   - Eyebrow label: "SHARE THIS INVITE CODE" (labelLarge, letterspaced)
   - Invite code rendered mono displayMedium with letter-spacing (e.g., `9 2 4 8 1 7`)
   - Actions row: [Copy] (BaktazButton.outlined -> toast "Code copied") + [Share] (BaktazButton.filled -> system share sheet)
3. **Countdown hero** (visual continuity with details screen): "STARTS IN" eyebrow + mono digits countdown (2d : 14h : 12m). HIDDEN if challenge already active. For PRIVATE challenges: replaced with policy text "Starts when you launch or after initial phase."
4. **YOUR ENTRY receipt ledger** (divider-separated rows, TERMS pattern):
   - Type: Public/Private
   - Entry Fee: paid amount
   - Starts: date
   - Ends: date
5. **Actions**: primary [View Challenge] full-width; text button [Back to Challenge Hub]

Zero new colors — reuse existing design tokens only.
