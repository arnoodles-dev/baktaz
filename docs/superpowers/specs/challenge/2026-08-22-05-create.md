## Server-Driven Configuration

**`ChallengeConfig`** endpoint returns all creation bounds from server:

```dart
// ChallengeConfig model
class ChallengeConfig {
  final int minDurationDays;       // default 30
  final int maxDurationDays;       // default 120
  final int maxParticipants;       // default 100
  final double minEntryFee;        // default 100.0
  final double maxEntryFee;        // default 10000.0
  final double maxHostCutPercentage; // default 5.0
  final int minParticipantsForPublic;   // default 2
  final int minParticipantsForPrivate;  // default 2
  final int minDailyStepCeiling;        // default 10,000 (anti-cheat threshold min)
  final int maxDailyStepCeiling;        // default 50,000 (anti-cheat threshold max)
  final int defaultDailyStepCeiling;    // default 30,000 (anti-cheat threshold default)
  final Map<RewardMode, int> rewardModeMinParticipants;  // per-mode floors
}
```

**Fetch flow:**
1. `ChallengeCreateCubit.init()` calls `getChallengeConfig()` endpoint
2. Cubit stores config in state
3. Form fields derive ranges from config
4. Config cached for session; refetched if admin changes

## Create Flow

1. User taps "Create Challenge" on default view.
2. **Launch Type Bottom Sheet** (`create_launch_type_sheet.dart`) pops up with two options:
   - 🌐 PUBLIC: "Open to anyone. Signup window before challenge starts."
   - 🔒 PRIVATE: "Invite-only. Start when min participants join."
3. User selects type → form opens with `launchType` param driving field visibility.
4. User fills form → taps "Create Challenge" → **Summary Bottom Sheet** (`create_challenge_summary_sheet.dart`) shows all entered values for review.
5. **TODO(payment)**: User confirms → creates payment intent for host entry fee → opens HitPay WebView
6. After successful payment → Success Screen with shareable invite code + CTA to view challenge.

## Reusable Form Fields (`challenge_create_form.dart`)

**All fields derive ranges from `ChallengeConfig`:**

- **BASICS Section**:
  - Challenge Title: Required (`BaktazTextField`).
  - Description: Optional (multiline). Shown truncated (1 line, ellipsis) on explore cards; full text on details screen; included in summary sheet.

- **STAKES Section**:
  - Entry Fee: Required slider, range from `config.minEntryFee` to `config.maxEntryFee`.
  - **TODO(payment)**: Host Cut Percentage (configurable, range from 0 to `config.maxHostCutPercentage`, default 0.5%) — shown in STAKES section, only visible to host during creation.

- **RULES Section**:
  - Duration: Required slider, range from `config.minDurationDays` to `config.maxDurationDays` (same range for both public and private).
  - Max Participants: Required stepper, floor from `config.rewardModeMinParticipants[rewardMode]`, cap from `config.maxParticipants`.
  - Reward Mode (Q93 Option A): Required radio — 4 options:
    - `winnerTakesAll` — "All In" — 100% to 1st place
    - `top3TieredSplit` — "Podium Model" — recommended default
    - `goalThresholdEqualProfitShare` — "Habit Builder"
    - `milestoneHybrid` — "Hybrid Model"
    Drives which additional fields shown (tie-breaker, step goals, reward breakdown).
  - Tie-Breaker: Conditional dropdown + tooltip button. Shown only when Reward Mode is Winner-Takes-All or Top 3 Tiered Split. Hidden for Goal-Threshold and Hybrid (goal-based, no ranking ties). Default pre-selected "Equal Split". Options: `equalSplit`, `suddenDeath`, `consistencyMetric`. Required when maxParticipants >= 3 for WTA mode. Tooltip explains how each rule works.
  - **Daily Step Ceiling (Anti-Cheat Threshold)**: Required slider in RULES section, range from `config.minDailyStepCeiling` (10,000) to `config.maxDailyStepCeiling` (50,000), default `config.defaultDailyStepCeiling` (30,000). Tooltip: *"Participants logging steps above this daily threshold will be automatically flagged for anti-cheat community review."*

- **LAUNCH Section**:
  - Launch Type (Q94 Option A): Set by bottom sheet selection, not form field. `public` or `private`. Drives visibility of launch-specific schedule: `ChallengeSchedule` dateRange UI.

## Dynamic Min Participants Mapping

Floor for max participants stepper (from `config.rewardModeMinParticipants`):

- Winner-Takes-All: 2
- Top 3 Tiered Split: 3
- Goal-Threshold Equal Profit Share: 2
- Milestone Hybrid: 2

## Schedule Section Model

### Public Schedule

- Duration slider: `config.minDurationDays` to `config.maxDurationDays`.
- Initial Phase slider:
  - Minimum: 2 days.
  - Maximum: `AppConfig.publicInitialPhaseMaxDays`.
  - Default: 14 days.
- Start Policy copy: "Auto-starts after initial phase."
- Starts: Read-only computed date = `now + initial phase`.
- Ends: Read-only computed date = `starts + duration`.
- **Min participants for launch**: `config.minParticipantsForPublic` (default 2). If public competition fails to meet this minimum by start date, host entry fee is forfeited while participant entry fees are 100% refunded via HitPay.

### Private Schedule

- Duration slider: `config.minDurationDays` to `config.maxDurationDays`.
- Initial Phase slider:
  - Minimum: 1 day.
  - Maximum: `AppConfig.privateInitialPhaseMaxDays`.
  - Default: 30 days.
- Start Policy copy: "Host can start manually once min participants join. Auto-starts after initial phase if min participants joined."
- Starts:
  - Manual when host starts before phase end after minimum participants join.
  - Computed auto date when initial phase ends and minimum participants joined.
- Ends: duration after actual start.
- **Min participants for launch**: `config.minParticipantsForPrivate` (default 2). Host can start manually once this minimum is reached.

### Private Manual Start Semantics

- Minimum participants reached before phase end:
  - Host can tap `Start Challenge Now` manually.
  - Confirmation dialog (`start_challenge_confirmation_dialog.dart`) shows new Ends date (`start time + duration`).
  - Confirming manual start updates End Date = start time + duration.
- Phase ends with minimum participants reached:
  - Challenge auto-starts.
- Phase ends without minimum participants:
  - Challenge stays pending until 30-day auto-cancel or host archives.
